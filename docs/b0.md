# B0: local LLM without compiler remarks

Check `results/results_llm_no_remarks.txt` for the current run status and results.
The saved report is complete: all 151 kernels and 755 independent rewrites were
attempted. Of those rewrites, 387 passed the checks. The report retains a winning
rewrite for 136 kernels; the remaining 15 have no correctness-passing rewrite.

This run used Qwen2.5-Coder 7B Instruct FP16, an 8192-token context, temperature
0.8, a 4096-token output limit and Clang 14.0.0 on Linux. The report preserves
the actual compiler/platform information and source/prompt hashes. Earlier
interrupted runs are kept privately in the ignored `.local/previous-runs/` folder.
The Python runner and model transport are independent of the execution machine.

To evaluate vectorization of the saved winners without generating more rewrites,
see [the saved-code vectorization check](b0_vectorization.md).

## Behavior

- Use all **151 TSVC kernels** by default.
- Request **5 independent rewrites per kernel**, each starting from the original
  function and the shared `prompts/agent.txt` template. Its feedback is exactly
  `No compiler feedback is available.` There is no repair/retry conversation.
- Strip TSVC's descriptive comments from the prompt so embedded optimization
  hints are not supplied as feedback. Preserve executable code and strings.
- Keep temperature 0.8, the configured output/context limits, and sampling seed
  `583 + trial - 1`. Use the same prompt/settings for every candidate.
- Require the original function signature, benchmark setup, timing/checksum/dummy
  calls and repetition loops to remain intact. Pragmas, SIMD intrinsics and
  assembly are prohibited by the shared prompt and checked by the validator.
- Compile and compare each candidate with the original on both full-size TSVC
  data and a smaller workload (`iterations=640`, `LEN_1D=320`, `LEN_2D=40`).
- Check the returned checksum, global float arrays, integer/index arrays and
  originally allocated `xx` buffer. Float tolerance is
  `1e-3 + 1e-4 * abs(original)`; integers must match exactly. Equal signed
  infinities match; NaNs are inconclusive and not accepted as correct.
- Use **one full-size timed invocation per candidate**. Its checksum and runtime
  come from that same invocation. There are no timing repetitions or medians.
- Keep the **lowest measured time among candidates that pass all checks**.
  Discard every other candidate. If none passes, report `no_correct_rewrite`.

With defaults this schedules **755 model generations**.

## Only one saved result file

The sole persistent output is **`results/results_llm_no_remarks.txt`**. A short
header records the model, compiler, source/prompt hashes and experiment settings.
Each kernel's section contains only its winning runtime, checksum and rewritten
C function (or its no-correct-rewrite/not-run status). There is no per-trial CSV,
JSON, prompt archive, rewritten-source folder or separate manifest.

For illustration only, a completed kernel section looks like:

```text
========================================================================
Kernel: s212
Status: correct
Time (seconds): <fastest correct candidate's measured time>
Checksum: <checksum from that same execution>
Rewritten code:
<the fastest correct rewritten C function>
```

The file is updated as the experiment progresses. Only the current winner for
any kernel is held in memory; discarded trial outcomes are not accumulated.
Compilation and state snapshots use temporary directories that are removed
when each candidate finishes. Raw local-model response logging is disabled.
Existing result files are never overwritten: use `--output another_file.txt`
for a separate experiment. An interrupted run retains its best results so far,
with an interrupted/failed status in the same file. There is no resume mode.

## Preview without running anything

From the project root:

```powershell
python -m src.llm_without_remarks --dry-run
python -m src.llm_without_remarks --dry-run --kernels s212 --trials 1
```

Omitting `--run` also previews only. Preview makes no model/server requests,
compiles no C, executes no benchmarks, and creates no experiment files.

`--kernels s212 s233 ...` selects an explicit subset. `--limit 25` selects the
first 25 kernels in `results/loop_status.csv` order. `--non-vectorized-only`
restricts the experiment to 66 previously nonvectorized kernels;
`--all-kernels` explicitly selects the default full set. `--trials N` overrides
how many independent rewrites to try per kernel.

On a system where Python, Clang and Ollama are directly accessible, run:

```powershell
python -m src.llm_without_remarks --run
```

This command runs B0 directly using the local Ollama server. A notebook is not
required; the Python runner handles generation, correctness checks, timing and
writing the result file.

## Measurement and prerequisites

The driver retains TSVC's original `init()` and per-kernel argument expressions,
including index pointers and compound-struct arguments. It zeroes the allocated
`xx` buffer before calling the kernel to make state snapshots deterministic.
The downloaded source and existing original baseline files are never changed.

Timing uses a monotonic timer around the kernel function. It excludes process
startup and snapshot writes, but includes setup and checksum work inside that
function. This differs from the legacy baseline file's internal loop timer.
The runner executes original and rewritten code on the same machine with the
same compiler flags and workload settings. These deterministic differential
checks do not constitute formal or exhaustive correctness verification.

To match the saved model settings for a future run, set `OLLAMA_MODEL` to
`qwen2.5-coder:7b-instruct-fp16` and `OLLAMA_NUM_CTX` to `8192` before starting
Python. Start Ollama with that model and provide a
Clang toolchain that can build POSIX-oriented TSVC (`sys/time.h`,
`posix_memalign`, math library). Set `CC_BIN` or use `--compiler`. Linux/macOS/WSL
or a suitable MinGW Clang toolchain is required; an MSVC-only toolchain needs
compatibility support. The default laptop configuration uses Q4_K_M and a
4096-token context, so those defaults do not reproduce the saved FP16 run.
Use matching compiler settings and measure original/rewrite pairs on the same
machine for runtime comparisons.

## Files and offline tests

- `src/llm_local.py`: local model transport, with raw logging disabled by default.
- `src/llm_without_remarks.py`: dataset selection, prompting, winner selection
  and the single text report.
- `src/tsvc_benchmark.py`: temporary C builds, state checking and kernel timing.
- `tests/test_b0.py`: offline tests with mocked model responses. The native C
  integration test is explicitly skipped when Clang is unavailable.

```powershell
python -m unittest discover -s tests -v
```
